# ✅ Tests Summary
{: .no_toc }

**Location:** `.github/scripts/tests-summary/main.py`

A zero-dependency Python script that reads one or more test and coverage
report files and writes Markdown output suitable for GitHub Actions step
summaries and pull-request comments.

## What it does

`tests-summary` acts as a report aggregator.  For every enabled report source
whose file exists on disk it:

1. Parses the file using the appropriate parser.
2. Produces a **detailed Markdown section** (written to `--summary-out`) that
   can be appended directly to `$GITHUB_STEP_SUMMARY`.
3. Optionally produces a **compact Markdown section** (written to
   `--comment-out`) that can be posted or updated as a pull-request comment.

All sections are concatenated with a horizontal rule (`---`) so the final
output is one coherent document regardless of how many sources are active.

---

## Supported report formats

### Coverage

| Format | Flag | Default path | Notes |
|--------|------|-------------|-------|
| LCOV | `--lcov` | `lcov.info` | Generated by `pytest-cov` with `--cov-report=lcov` or by `gcov`/`llvm-cov` |

### Test results

| Format | Flag | Default path | Notes |
|--------|------|-------------|-------|
| JUnit XML | `--junit` | `junit.xml` | The universal test-results format; supported by pytest, Maven, Gradle, Jest, Go, etc. |
| pytest-json-report | `--pytest-json` | `.report.json` | Richer detail via the [`pytest-json-report`](https://github.com/numirias/pytest-json-report) plugin |

Each source is **optional**.  If the file does not exist the source is silently
skipped, so you do not need to pass `--no-<name>` flags in pipelines that only
produce a subset of the reports.

## CLI reference

```text
usage: main.py [-h]
               [--lcov PATH] [--no-lcov]
               [--junit PATH] [--no-junit]
               [--pytest-json PATH] [--no-pytest-json]
               [--summary-out PATH] [--comment-out PATH] [--run-url URL]

Coverage sources:
  --lcov PATH          Path to LCOV coverage file (default: lcov.info)
  --no-lcov            Disable LCOV coverage report

Test result sources:
  --junit PATH         Path to JUnit XML report (default: junit.xml)
  --no-junit           Disable JUnit XML test results
  --pytest-json PATH   Path to pytest-json-report file (default: .report.json)
  --no-pytest-json     Disable pytest-json-report test results

Output options:
  --summary-out PATH   Output path for the detailed step-summary Markdown
                       (- for stdout, which is the default)
  --comment-out PATH   Output path for the brief PR-comment Markdown
  --run-url URL        GitHub Actions run URL to embed as a hyperlink in
                       PR comment output
```

## Architecture

The script is structured around three layers:

```
Data models  →  Parsers  →  Formatters
```

### Data models

| Class | Purpose |
|-------|---------|
| `FileRecord` | Coverage metrics for a single source file |
| `CoverageSummary` | Aggregated coverage across all files, plus a reference to its source format |
| `TestCase` | A single test case with name, status (`passed`/`failed`/`skipped`/`error`), duration, and optional message |
| `TestSuite` | A named collection of `TestCase` objects (mirrors a JUnit `<testsuite>`) |
| `TestResults` | Aggregated test results across all suites, plus a reference to its source format |

### Parsers

Each parser is a subclass of `CoverageParser` or `TestResultsParser` with a
single `parse(path: Path)` method that returns the appropriate data model.

| Class | Input | Returns |
|-------|-------|---------|
| `LcovParser` | `lcov.info` | `CoverageSummary` |
| `JunitParser` | JUnit XML | `TestResults` |
| `PytestJsonParser` | pytest-json-report JSON | `TestResults` |

`JunitParser` handles both `<testsuites>` (multi-suite) and bare `<testsuite>`
root elements.

`PytestJsonParser` maps pytest's extended outcome values (`xfailed`, `xpassed`)
to the canonical `skipped`/`passed` statuses.

### Formatters

| Function | Input | Output |
|----------|-------|--------|
| `format_test_results_summary` | `TestResults` | Detailed Markdown with counts table, failed-test list, and per-suite breakdown |
| `format_test_results_comment` | `TestResults` | Compact Markdown with counts table and collapsible failed-test list |
| `format_coverage_summary` | `CoverageSummary` | Detailed Markdown with overall metrics and collapsible per-file breakdown |
| `format_coverage_comment` | `CoverageSummary` | Compact Markdown with overall metrics and collapsible lowest-coverage files |

### Registry

`COVERAGE_SOURCES` and `TEST_SOURCES` are lists of `CoverageSource` /
`TestSource` dataclasses that wire together a name, default path, parser
instance, and formatter functions.  The main loop iterates these lists, so
adding a new format requires only:

1. Implementing a parser subclass.
2. Adding an entry to the appropriate list.
3. Adding the corresponding `--<name>` / `--no-<name>` CLI arguments.

## Dependencies

The script uses only the Python **standard library** (`xml.etree.ElementTree`,
`json`, `argparse`, `pathlib`, `dataclasses`, `abc`).  No packages need to be
installed to *run* the script.

The `pyproject.toml` bundled alongside the script provides:

- **`[project.optional-dependencies] pytest-reports`** — install these in the
  environment that *generates* the reports (`pytest-cov`, `pytest-json-report`).
- **`[project.optional-dependencies] dev`** — development dependencies for
  testing the script itself.

```bash
# Install report-generation dependencies into your project venv:
pip install "pytest-cov>=4.1" "pytest-json-report>=1.5"
```

## Usage in GitHub Actions

### Minimal — step summary only

```yaml
- name: Run tests
  run: |
    pytest --cov --cov-report=lcov:reports/lcov.info \
           --junit-xml=reports/junit.xml \
           --json-report --json-report-file=reports/.report.json

- name: Generate summary
  if: always()
  run: |
    python .github/scripts/tests-summary/main.py \
      --lcov   reports/lcov.info \
      --junit  reports/junit.xml \
      --pytest-json reports/.report.json \
      --summary-out reports/step-summary.md
    cat reports/step-summary.md >> "$GITHUB_STEP_SUMMARY"
```

### Full — step summary + PR comment

```yaml
- name: Run tests
  run: |
    pytest --cov --cov-report=lcov:reports/lcov.info \
           --junit-xml=reports/junit.xml \
           --json-report --json-report-file=reports/.report.json

- name: Generate reports
  if: always()
  run: |
    python .github/scripts/tests-summary/main.py \
      --lcov   reports/lcov.info \
      --junit  reports/junit.xml \
      --pytest-json reports/.report.json \
      --summary-out reports/step-summary.md \
      --comment-out reports/pr-comment.md \
      --run-url "${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}"
    cat reports/step-summary.md >> "$GITHUB_STEP_SUMMARY"

- name: Find existing comment
  if: github.event_name == 'pull_request'
  uses: peter-evans/find-comment@v4
  id: find_comment
  with:
    issue-number: ${{ github.event.pull_request.number }}
    body-includes: "<!-- coverage-report -->"
    token: ${{ inputs.token }}

- name: Post or update PR comment
  if: github.event_name == 'pull_request'
  uses: peter-evans/create-or-update-comment@v5
  with:
    comment-id: ${{ steps.find_comment.outputs.comment-id }}
    issue-number: ${{ github.event.pull_request.number }}
    body-path: reports/pr-comment.md
    edit-mode: replace
    token: ${{ inputs.token }}
```

### Coverage only

```yaml
- name: Generate coverage summary
  run: |
    python .github/scripts/tests-summary/main.py \
      --lcov coverage/lcov.info \
      --no-junit --no-pytest-json \
      --summary-out "$GITHUB_STEP_SUMMARY"
```

### Test results only (no coverage)

```yaml
- name: Generate test summary
  run: |
    python .github/scripts/tests-summary/main.py \
      --junit reports/junit.xml \
      --no-lcov \
      --summary-out "$GITHUB_STEP_SUMMARY"
```

## Extending the script

### Adding a new coverage format

```python
class MyCoverageParser(CoverageParser):
    def parse(self, path: Path) -> CoverageSummary:
        # ... parse your format and return a CoverageSummary ...

COVERAGE_SOURCES.append(
    CoverageSource(
        name="myformat",
        default_path="my-coverage.xml",
        parser=MyCoverageParser(),
        summary_formatter=format_coverage_summary,  # reuse existing formatter
        comment_formatter=format_coverage_comment,
    )
)
```

Then add the CLI arguments in `_build_arg_parser()`:

```python
cov.add_argument("--myformat", default="my-coverage.xml", metavar="PATH", ...)
cov.add_argument("--no-myformat", action="store_true", ...)
```

### Adding a new test-results format

Follow the same pattern using `TestResultsParser`, `TestSource`,
`TEST_SOURCES`, and `format_test_results_summary` / `format_test_results_comment`.

## Output format reference

### Step-summary output (`--summary-out`)

Contains one section per discovered report, separated by `---`:

```
## ✅ Test Results          ← test results section (if any test report found)

| ✅ Passed | ❌ Failed | …

### Failed Tests             ← only present when there are failures

<details>Per-suite breakdown</details>

---

## Coverage Report          ← coverage section (if lcov found)

### Overall

| Metric | Hit | Total | % |

<details>Per-file breakdown</details>
```

### PR-comment output (`--comment-out`)

A compact version of the same data, with HTML `<!-- … -->` anchor comments so
`peter-evans/find-comment` can locate and update the comment on subsequent runs:

```
<!-- test-results-junit -->
## ✅ Test Results

<details>Failed tests</details>

<!-- coverage-report -->
## 🟢 Coverage Summary

<details>Lowest coverage files</details>
```
